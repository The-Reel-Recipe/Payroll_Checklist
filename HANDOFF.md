# Payroll Checklist — Handoff

**What this is:** an interactive guide to the monthly payroll run, written for an HR person
who has never run payroll and has never seen the Airtable system. Open **`index.html`** in any
browser (double-click). Works offline, Mac or Windows.

Last updated **2026-08-30**.

---

## The run — 12 steps, 3 parts

**Part 1 — Get everything in and approved** *(the last few days of the month)*
1. **Chase the managers** — overtime (*Payroll › Overtime to approve*), plus KPIs and leave in *My Team*. HR chases; managers decide.
2. **Approve bonuses, advances & penalties** — HR's own page. Approve or reject; never leave Pending.
3. **Decide which warnings cost money** — HR sets *Financial Status*. Only **Approved for Deduction** reaches pay.
4. **Working Days Calendar** — holidays, closures, extra grace, lateness off.
5. **Salary cards & leavers** — everyone paid needs an Active card. Termination Date **then** the tick.
6. **Import attendance** — *TRR Attendance* page → **Update attendance**, then check *Attendance Monthly*.

**Part 2 — Build the payslips** *(nothing is sent to anyone)*
7. **Read *Payslip Readiness*, then tick *Generate Payslips Now*** — the box unticks itself when done.
8. **Read *Card Check Result*** — names who to fix; fix, re-tick, re-read until ✅.
9. **Empty the *Needs fixing* tab** on the Payslips page — read the *Checklist* column, fix the cause, it clears itself.
10. **Sense-check** *Net Pay* on the *Ready to approve* tab.

**Part 3 — Approve & pay** *(one-way)*
11. **Approve** — snapshots and freezes every figure. Nothing sent yet.
12. **Mark Paid** — this is what emails the employee. Only after the transfer.

## Key facts baked into the wording (don't undo these)

- **HR works only from the Payroll interface**, never the raw tables.
- **Managers own overtime, leave, KPI ratings and delivery sign-off.** HR chases but cannot decide.
  **HR owns** adjustments, warning *Financial Status*, the calendar, salary cards, and the run.
- **Payslips are generated by ticking a box, not automatically.** The box unticks itself when the
  run finishes, and re-ticking is always safe — never duplicates, never touches an approved payslip.
- **Two checks, in this order.** *Payslip Readiness* runs **before** the tick and only sees
  month-linked inputs (overtime, adjustments, KPIs). Salary-card and attendance problems can only be
  found **after** generation, so they are written into *Card Check Result* by name.
- **The *Needs fixing* tab is the working list.** The *Checklist* column is populated on Draft
  payslips — HR does not need to set anything to *Under Review* first to see what is wrong.
- **Termination: date first, then the tick.** Ticking with an empty date stamps today.
- **Leave must be approved before the attendance import**, or an approved day off is charged as absence.
- **The payslip email is what "Paid" sends** — for the first live month it is switched on last.
- Attendance rules quoted in the guide come from *Payroll Settings*: start **10:00**, grace **11 min**,
  half-day threshold **31 min**, quarter day **0.25**, half day **0.5**, full absence **1**,
  divisor **30**, **8** hrs/day, overtime **×2**, penalty cap **22** days.

## Editing the guide

It is one self-contained HTML file — no build step, no dependencies.

**A step** is one `<li class="task" data-i="N">` block. Keep `data-i` sequential from `0`;
the saved-progress array is indexed by position, so inserting a step mid-list shifts
everyone's saved ticks by one.

Inside a step:

| Part | Element |
|---|---|
| Owner badge | `<span class="own you">` or `<span class="own mgr">` |
| Short title | `<span class="t">` |
| One-line summary | `<span class="s">` |
| Where to go | `<p class="where">` |
| Why it matters | `<p class="why">` |
| The steps | `<ol class="do">` |
| Callouts | `<div class="note stop\|warn\|tip">` — the **first** `<b>` becomes the heading |
| Screenshot | `<figure class="shot">` with an `<img>` and a `<figcaption>` |

**A blocker message** is one `<details class="bk">` in `#bklist`. If you add one, update the
`12 messages` count in that section's `<summary>`. The search box filters on the whole text of
each entry, so no tagging is needed.

**Inline styles used in the prose:** `.ui` (a page or button name), `.f` (a field name),
`.code` (a literal value to type), `.set` (a value to select).

## Saved progress

Ticks are kept in `localStorage` under `trr-payroll-run`, keyed by the month typed at the top:

```
{ "seenBrief": 1, "lastMonth": "Aug26", "months": { "aug26": [1,1,0, ...] } }
```

Typing a different month loads that month's ticks and starts clean if it has none. The reset
button clears only the month currently shown. Everything is wrapped in `try` / `catch`, so the
guide still works where storage is blocked — it just won't remember.
